# Отчёт для тестировщика — расширение R.I.P Market

**Версия:** **0.6.34**  
**Сайт:** https://p2pcs.ru  
**Файл:** `browser-extension/rip-market-browser-extension-v0.6.34.zip`  
**Дата:** 27 августа 2026  

Документ написан **простыми словами**: что уже сделано и как это проверить руками.

---

## 1. Что это за расширение (одной фразой)

Помощник для безопасных сделок на **R.I.P Market** внутри Chrome + Steam:

- продавец выставляет скины и отправляет обмен;
- покупатель видит «наш» оффер и принимает его **только в Steam**;
- расширение **никогда само** не жмёт Steam Guard и **не принимает** обмен без явного действия человека.

**Только Chrome.** Firefox / Safari — не тестируем.

---

## 2. Что расширение НЕ делает (важно)

| Не делает | Почему |
|-----------|--------|
| Не подтверждает Steam Guard | Только телефон / Steam Mobile |
| Не принимает обмен «само» | Покупатель жмёт Accept в Steam (иногда с подсказкой) |
| Не продаёт на Steam Community Market | Зелёная кнопка **Sell** справа — это Steam, не мы |
| Не хранит скины «внутри» popup | Скины остаются в Steam; мы рисуем кнопки поверх |
| Не список всех лотов в popup (пока) | Лоты — на сайте и в инвентаре Steam |

---

## 3. Установка (обязательно перед тестом)

1. Скачать zip **v0.6.34** (или взять локальный `rip-market-browser-extension-v0.6.34.zip`).
2. Распаковать. Нужна папка с `manifest.json` (часто это `dist` внутри zip).
3. Chrome → `chrome://extensions` → **Режим разработчика** → **Загрузить распакованное** → выбрать папку.
4. Проверить версию в popup: **«Версия 0.6.34»**.
5. После каждой смены zip: снова загрузить / обновить расширение и **обновить вкладку Steam (F5)**.  
   Иначе будет ошибка «Extension context invalidated» — это не баг сайта, а старая вкладка.

---

## 4. Подключение к сайту (pair)

1. Войти на **p2pcs.ru** тем же Chrome-профилем, где стоит расширение.
2. Аккаунт → **Подключить расширение**.
3. Открыть popup (иконка R.I.P):
   - зелёная полоска **«Подключено…»**;
   - **«Сайт и Steam совпадают»** (или понятная ошибка, если Steam другой).

**Ок:** popup зелёный, опрос «только что» / недавно.  
**Плохо:** красный / «переподключить» / Steam не совпадает.

## 5. Карта продукта: где что живёт

| Где | Зачем |
|-----|--------|
| **Popup** (иконка) | Пульт: связь, сделки «что делать сейчас», покупки/продажи, поддержка |
| **Steam инвентарь CS2** | Продать / мультипродажа / цены / бейджи |

## 6. Что реализовано и как тестировать

Ниже каждый блок: **что есть** → **как проверить** → **ожидание**.

---

### A. Popup — пульт сделок

**Что есть**

- Статус связи (сайт + Steam).
- Опрос / Steam rate limit / версия.
- Блок **«Требует действия»** (Guard, Accept, mismatch…).
- Секции **Покупки** / **Продажи** — когда есть активные сделки с сервера.
- Если сделок нет: **«Всё спокойно»** — это нормально, не баг.
- Кнопки: открыть сайт, обновить статус/сделки, отчёт для поддержки, отключить.

**Как тестировать**

1. Pair → открыть popup.  
2. Без сделок → «Всё спокойно».  
3. Сделать тестовую покупку/продажу (см. раздел B) → **Обновить сделки**.  
4. Должны появиться карточки с **одним главным** действием.

**Ожидание:** пустой спокойный экран без ордеров; с ордерами — список и понятный следующий шаг.

**Не путать:** активные **лоты** (объявления) в popup пока **не** списком. Лоты смотреть на сайте / в инвентаре.

---

### B. Продавец: автоотправка обмена (ядро)

**Что есть**

- После оплаты лота сервер даёт задачу расширению.
- Расширение открывает/заполняет обмен в Steam и отправляет.
- На сайте заказа фазы двигаются (черновик → отправлено → ждём Guard…).
- Guard только вручную в Mobile.

**Как тестировать (минимум)**

1. Продавец: pair + Trade URL + tradable скин.  
2. Покупатель (другое окно/инкогнито): купить лот.  
3. У продавца: расширение шлёт оффер; при запросе Guard — подтвердить в телефоне.  
4. На странице заказа фазы обновляются без вечного «залипания».

**Ожидание:** оффер ушёл один раз (не два), Guard не «проглатывается» молча.

Подробный happy path: [QA-EXTENSION-TESTING.md](./QA-EXTENSION-TESTING.md).

---

### C. Покупатель: безопасный Accept

**Что есть**

- На странице конкретного `tradeoffer/…` — большая плашка: скин совпал / не совпал.
- При mismatch — **не принимать**, ссылки на заказ/спор.
- Подсказка Accept (двойное подтверждение, не авто-клик «втихую»).
- В popup — покупки с CTA «Открыть проверенный оффер».

**Как тестировать**

1. Дойти до оффера покупателя.  
2. Открыть ссылку оффера из popup/заказа.  
3. Верный скин → статус ок, можно принимать в Steam.  
4. (Если возможно) подмена/чужой оффер → mismatch / «не наша сделка».

**Ожидание:** расширение **не** жмёт Accept само без явного шага пользователя.

---

### D. Steam инвентарь CS2 — продажа с сетки

**Что есть (0.6.34)**

- Синяя полоска R.I.P под сеткой.
- На **каждой** видимой ячейке: синяя **«Продать»** (или «Управлять» / блок).
- Справа у выбранного скина: синяя **«Продать на R.I.P»** рядом с **зелёной** Steam Sell.
- Цены / bid / «вам» (когда pair и API отдали цены).
- Бейджи: На R.I.P, В сделке, Trade-lock…
- Поддержка новых id Steam: `730_2_…` и `730_16_…` (Trade Protected).
- У `730_16_…` продажа может быть **приглушена** — это правильно (предмет с защитой).

**Как тестировать**

1. Pair → открыть  
   `steamcommunity.com/…/inventory/#730_2`  
2. **F5** после установки расширения.  
3. На карточках есть синяя **Продать** (не путать с зелёной Sell справа).  
4. Клик по скину → справа тоже синяя R.I.P.  
5. Клик синей → панель цены → Выставить → тост / лот на сайте.  
6. Уже выставленный → **Управлять** (цена / снять).

**Быстрая проверка в консоли** (вкладка Steam, после `allow pasting` если попросит):

```js
({
  holdersAttr: document.querySelector('#rip-market-inventory-layer')?.getAttribute('data-item-holders'),
  steamItems: document.querySelectorAll('.item[id^="item730_"], .item[id^="730_"]').length,
  ourOverlays: document.querySelectorAll('.rip-item-enrich').length,
  ourSellButtons: document.querySelectorAll('.rip-item-sell').length,
})
```

**Ожидание при загруженной сетке:** цифры `holdersAttr` / `ourOverlays` / `ourSellButtons` **больше 0**.

**Плохо:** host есть, а цифры 0 — писать в баг с этим объектом + скрин.

Подробнее: [QA-INVENTORY-OVERLAY-0.6.34.md](./QA-INVENTORY-OVERLAY-0.6.34.md).

### E. Множественная продажа

**Что есть**

- Кнопка **«Множественная продажа»** на host bar.
- Чекбоксы на карточках.
- Низ: Выбрано / Выставить / Очистить / Выйти.
- Одна цена на пачку; итог created/failed.

**Как тестировать**

1. Включить мульти.  
2. Выбрать 2–5 простых предметов (лучше без float, если проверяете bulk API).  
3. Выставить → на сайте появились лоты / частичный успех понятен.

**Ожидание:** без чекбоксов на сетке мульти «мёртвый» — сначала должен работать раздел D.

---

### F. Список обменов Steam (`/tradeoffers/`)

**Что есть**

- Бейджи: Сделка R.I.P / Подозрительно / Не наша.
- Фильтр «только наши».
- Помощь продавцу «Собрать оффер».
- Помощь покупателю «Принять (Steam)» → на страницу оффера.

**Как тестировать**

1. Иметь активный оффер R.I.P.  
2. Открыть список tradeoffers.  
3. Наш оффер помечен; чужой — нет или «не наша».

---

### G. Уведомления Chrome

**Что есть**

- Редко и по делу: Guard / пора Accept / mismatch / новая продажа.
- Не спам на каждый опрос.
- Можно приглушить сделку / выключить в «Дополнительно».

**Как тестировать**

1. Дойти до Guard / Accept.  
2. Пришло 1 уведомление на смену состояния, не пачка каждую секунду.

---

### H. Безопасность и сбои

**Что есть**

- Safe mode: сайт недоступен → list/send/управление лотом режутся, кэш сделок может остаться.
- Отчёт для поддержки одной кнопкой.
- Steam Web API key — только «для поддержки», не обязателен обычному пользователю.

**Как тестировать**

1. Popup → скопировать отчёт — в буфере текст с version / order.  
2. (Опционально) оборвать сеть к сайту → появляется safe mode, выставить лот нельзя.

---

### I. Онбординг

**Что есть**

- Короткие шаги в popup: установил → pair → инвентарь → пробный list.  
- Подсказка на инвентаре «нажми синюю Продать».

**Как тестировать**

1. Чистый pair → видны шаги.  
2. Зайти в CS2 inventory → шаг инвентаря отмечается.  
3. Выставить один скин → онбординг закрывается / завершается.

## 7. Чеклист «минимальный проход» (30–40 мин)

Отметь галочками:

- [ ] Установлено **0.6.34**, после установки F5 на Steam  
- [ ] Pair на p2pcs.ru, popup зелёный, Steam совпадает  
- [ ] Инвентарь CS2: синие **Продать** на сетке  
- [ ] Выбранный скин: синяя R.I.P рядом с зелёной Steam Sell  
- [ ] Один list с панели → лот на сайте  
- [ ] Мульти: чекбоксы + выставить ≥2  
- [ ] Покупка лота → у продавца уходит оффер (или понятный fallback)  
- [ ] Guard только вручную  
- [ ] У покупателя overlay «наш оффер» / verify  
- [ ] Popup: при живой сделке карточка + «Обновить сделки»  
- [ ] Нет авто-Accept / авто-Guard

## 8. Частые путаницы (не баги)

| Видишь | На самом деле |
|--------|----------------|
| Зелёная **Sell** справа | Steam Market, не R.I.P |
| «Всё спокойно» в popup | Нет **сделок**, требующих действия / нет активных ордеров в опросе |
| Приглушённая Продать на `730_16_*` | Trade Protected — так задумано |
| После обновления расширения кнопки пропали | Забыл F5 на вкладке Steam |
| Красный `500` в консоли Steam | Сервер Steam не отдал инвентарь — сетка/оверлеи могут быть пустыми |

## 9. Как оформить баг

В тикет обязательно:

1. Версия из popup (**0.6.34**?).  
2. Роль: продавец / покупатель.  
3. URL страницы (inventory / tradeoffer / сайт).  
4. Скрин.  
5. Для инвентаря — объект из консоли (раздел D).  
6. Что нажали и что ожидали.
